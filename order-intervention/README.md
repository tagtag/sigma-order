# 順序介入 — マスク生成モデルにおける固定テキストのエントロピー生成

2026-11-09 / 田口善弘・Astra

対象論文: T. Sagawa, *Stochastic Thermodynamics for Autoregressive Generative
Models: A Non-Markovian Perspective*, PRX Intelligence **1**, 023013 (2026),
[arXiv:2604.07867](https://arxiv.org/abs/2604.07867),
コード/データ: https://github.com/taksagawa/Paper2026

## 何をする実験か

沙川論文の第VIII節は、未解決問題をこう名指ししている。

> ブロック水準のエントロピー生成は、少なくとも三つの絡み合った寄与を反映している。
> 記述された事象の間の真の因果依存、因果関係のない単なる時間順序、そして談話構造の
> 慣習(物語の弧、修辞的構成など)である。これらの寄与を解きほぐすことは、
> 極めて非自明な未解決問題として残っている。

**自己回帰モデルではこれを分離できない。** 生成順序がテキストの順序に固定されている
からである。マスク(任意順)生成モデルでは分離できる: **テキストを固定したまま、
アンマスク順序 π を振る。**

- 分離が π に不変 → 矢は**内容**が担っている
- 分離が π に依存 → その一部は**生成プロトコルの産物**

## 理論的な位置づけ

アンマスク順序 π を固定すると、マスクモデルは任意順連鎖律により**正規化された同時分布**を定義する。

    log P_pi(x) = sum_{t=1..L} log p_theta( x_{pi(t)} | x_{pi(1..t-1)}, 残りはマスク )

第 t 段では位置 π(1..t−1) が真のトークンを持ち、それ以外(π(t) 自身を含む)は
`[MASK]`。モデルの位置 π(t) における分布を読む。

重要な帰結: **π を固定するごとに、マスク拡散モデルは沙川のクラスの自己回帰モデルに
なる。** 部分的に埋まった列が決定論的な内部状態、$p_\theta$ が明示的な放射核。
したがって枠組みはそのまま適用でき、$\sigma_\pi$ は厳密に計算できる。新しいのは
**π が自由パラメータである**点で、ARは π = 恒等に固定されている。

(順序平均 $\log \mathbb{E}_\pi[P_\pi(x)]$ は各順序の同時分布ではなく、通常の
マスク拡散の学習目的関数はこれを下から押さえる。ここでは π を固定し、
すべての量を真の対数確率に保つ。)

### 順序と反転を混同しないこと

- **反転**はどの列を採点するかを決める(順方向 / トークン反転 / ブロック反転)。
  これが沙川のプロトコル反転。
- **順序**はその列の対数確率をどう計算するかを決める。

忠実な移植は **π を位置空間で固定したままテキストを反転する**。ARで生成順序が
左→右のままテキストだけ反転するのに対応する。`--order-follows-text` は順序も
テキストと一緒に反転する変種で、ベイズ的遡及に近い。既定ではなく診断用。

反転の規約は参照実装(`gpt2/text_sets/gpt2_input_text.py`)に合わせた。
トークン反転は全ID反転、ブロック反転は文末句読点(`. ! ?`)で分割して
**ブロック順のみ反転、ブロック内は保存**。BOS は付けない(GPT-2 固有の処理で、
全位置をマスク文脈から採点するマスクモデルには対応物がない)。

## 検証済みの部分

`aoar_selftest.py` は**モデルの重みなしで実行できる**。整合的な条件付き分布を
与えたとき任意順連鎖律は順序によらず $\log \pi(x)$ を返す、という厳密な性質を使う。

```

   max |log P_pi(x) - log pi(x)|  = 1.776e-15     -> PASS
2) PERTURBED provider: 順序依存が出ること(検定の検出力)

3) 固定順序で P_pi が正規化されていること
```

### ディスクの扱い

公式ドキュメント([quota](https://www.scl.kyoto-u.ac.jp/Attention/quota.html) /
[aptmp](https://www.scl.kyoto-u.ac.jp/Attention/aptmp.html))より:

| 領域 | 容量 | 性質 |
|---|---|---|
| ホーム | **既定 100 GB / 2,000,000ファイル**、申請で最大 1000 GB / 8,000,000 | `quota -v` で確認。**超過するとホームに一切書けなくなる** |
| `/aptmp/<user>` | 容量記載なし、課金対象外、全計算サーバで共有 | ホーム容量を超える作業用。**空きが逼迫すると予告なく削除され得る** |
| `${TMPDIR}` | ジョブ開始時に自動生成、**終了時に自動削除** | 実体は `/scratch/pbs_tmpdir/<JobID>/`。ただし **APC/APG では Lustre 上**で、50TB SSD は SDF キューのみ |

**この計算自体はディスクをほとんど使わない。** 出力は1ジョブあたり JSON が
数百 kB、30ジョブ全体で 15 MB 程度。`${TMPDIR}` を経由する必要はなく、
APG の `${TMPDIR}` は Lustre なので速度上の利点もない。

容量を食うのは**モデルの重みだけ**(8B の bf16 で約 16 GB)。ここに落とし穴が二つある。

**落とし穴1: `--local-dir` は二重に持つ。**
`huggingface-cli download --local-dir DIR` は、版によって blob キャッシュと
`DIR` の**両方**に実体を置く。8B なら 16 GB のつもりが **32 GB** になる。
対策は単純で、**`--local-dir` を使わない**。キャッシュ1箇所に置き、
`HF_HUB_OFFLINE=1` のもとで**リポジトリIDのまま** `from_pretrained` に渡せば
transformers がキャッシュから直接読む。二重化も、パスの引き回しも消える。
ジョブに渡すのはパスではなく `MODEL_ID` にしてある。

**落とし穴2: 確認せずに落とす手順はだめ。**
`icr_prefetch_model.sh --check` が、**何も転送せずに**メタデータだけで実サイズを出し、
`/aptmp` の空きと突き合わせ、足りなければそこで止まる。`--check` を通してから
初めてダウンロードする。

方針:

- **重みはキャッシュ1部だけ `/aptmp` に。** 再取得できるので予告なく消えても困らず、
  ホームの 100 GB を空けておける。
- **結果はホームに。** 消えては困るので `/aptmp` には置かない。
- `TORCH_HOME`、Triton/pycache も `/aptmp` か `${TMPDIR}` に逃がす
  (`icr_job_single.sh` で設定済み)。放置するとホーム側に静かに溜まる。
- **終わったら消す。** `sh icr_prefetch_model.sh --purge`(モデルディレクトリ)、
  `--purge-all`(共有の Xet キャッシュごと)。

**Xet ストレージの注意**(`huggingface_hub` 2.x で実地確認):
取得後の実測が `models--GSAI-ML--LLaDA-8B-Base` で **6.1 MB**、
`$HF_HOME` 全体で **15 GB** だった。2.x は Xet ストレージを使い、
`hub/` 以下にはポインタしか置かず**実体は `$HF_HOME/xet/` にある**。
したがって、

- モデルディレクトリの `du -sh` は実サイズを示さない
- **モデルディレクトリだけ消してもほとんど解放されない**
- `xet/` は**全モデルで共有**なので、他に残したいモデルがあるときに消してはいけない

`--purge` はモデルディレクトリのみを消して `xet/` のサイズを表示し、
`--purge-all` が `xet/` も消す、という分離にしてある。

`icr_job_single.sh` は起動時に `quota -v`、`df`、キャッシュの実サイズを出力し、
**重みがキャッシュに無いか、コーパスが無ければその場で終了する**
(30ジョブ投げてから気づく事態を避ける)。

## 化研での落とし穴: `Qlist`(重要)

PBS の `Qlist` は**ノード側に定義されたサイト固有リソース**で、`select` チャンクの
中で要求しないとジョブはどのノードにも照合せず、

```
comment = Not Running: Insufficient amount of resource: Qlist
```

のまま永久に Q に居座る。混雑しているように見えるが、**要求漏れである**。
2026-11-09 に `pbsnodes -a | grep -i qlist | sort -u` で確認した値:

```
APG,sp,ssdb_r,ssdb_n,ssdb_p,EMERG
EMERG,TRAIN,SMALL
SMALL,APC,bio,sp,ssdb_r,ssdb_n,ssdb_p,EMERG
bio / cdb / koala
```

したがって:

```
#PBS -l select=1:ncpus=8:mem=12gb:Qlist=SMALL
#PBS -l select=1:ncpus=8:mem=64gb:ngpus=1:Qlist=APG
```

ジョブ全体のリソースとして `-l Qlist=SMALL` と書くのは**誤り**。ノードリソースなので
チャンク内に書く。サイトのサンプルスクリプトには `Qlist` が一切出てこないので、
ドキュメントからは気づけない。

**この要求漏れで APG ジョブ 5270920 が何週間も動かなかった。** GPU 混雑と誤認して
時間貸し GPU を借りたが、不要だった。本リポジトリの PBS スクリプト4本
(`icr_job_pll.sh`, `icr_job_single.sh`, `icr_job_grid.sh`, `icr_job_canary.sh`)は
すべて修正済み。

もう一点、**SMALL の上限を3つとも最大で要求しない**こと。12コア・48 GB・12時間は
すべて SMALL の上限値で、スケジューラがバックフィルできずノードが丸ごと空くまで
待つ。BERT-large は fp32 でも重み 1.3 GB、最大テンソルはロジットの
$64 \times 50 \times 30522 \times 4 \approx 390$ MB なので、**8コア・12 GB・3時間**で足りる。

## 設計上の注意

**計算量**: テキスト1本・1順序につき $3L$ 回のカーネル評価($L$ は
トークン長、順方向・トークン反転・ブロック反転の3列)。各列の $L$ 段は
**1回のバッチ順伝播にまとめている**ので、実際には1本あたり3バッチ。
沙川の固定テキストは短い($T \approx 25$–40)ので、H100 で1コーパス
200本が数分のオーダー。

**評価器の規模**: 再現解析で分かったことだが、GPT-2(117M)はブロック水準で
5コーパス中2つで有意差を出せず、Qwen3-4B-Base では5/5。**評価器は4B級以上が要る。**
8B のマスク拡散モデルはこの条件を満たす。

**なぜ BERT ではなく LLaDA か(2つの独立な理由)**: 出発点は「沙川の測定を
BERT でやり直す」だったが、BERT は**2つの別々の理由で**この測定の担い手に
なれない。

*(a) 同時分布を持たない。* BERT の条件付き確率 $p_\theta(x_k \mid x_{-k})$ の族は
一般にどの同時分布とも整合しない(長方形テスト、arXiv:2605.16378)。任意順連鎖律
$\log P_\pi(x) = \sum_t \log p_\theta(x_{\pi(t)} \mid x_{\pi(1..t-1)})$ で定義される
$P_\pi$ は順序 $\pi$ ごとに**別の**分布になり、「真の同時分布に対する前向き/
後ろ向き」という沙川の設定そのものが立たない。これが理論節で扱った退化極限。

*(b) マスク率が訓練分布の外に出る。* より実務的な理由。BERT は**常に15%程度の
マスク率**でしか訓練されていない。ところが任意順連鎖律の第1段は**100%マスク**、
第2段は $(L-1)/L$ マスクで、BERT が一度も見たことのない領域に入る。
虫食い状に散らばったマスク配置それ自体は BERT の訓練分布そのものなので
問題にならないが、**マスク率**が問題になる。LLaDA のようなマスク拡散モデルは
0% から 100% までの**あらゆるマスク率**で訓練されているので、第1段(全マスク)から
最終段(1箇所だけマスク)まで一貫した条件付き分布を与える。

要するに、**逆転の呪いを見るだけなら BERT でよいが、任意順の対数確率を厳密に
計算するには全マスク率で訓練されたモデルが要る**。

**統計**: 論文の方法記述は漸近+連続補正だが、GPT-2側の同梱コードは
`method="exact"`(Table II は exact、Table III は漸近)。結論は変わらないが
数値が数倍違うので、`aggregate_orders.py` は**両方を出力する**。

**帰無帯の較正(重要)**: `make_mock_results.py` で、順序依存を一切植え込まない
コーパスと植え込んだコーパスを作って集計器にかけたところ、

| 合成コーパス | 順序間 $r$ の spread | sd |
|---|---|---|
| MockInvariant(順序依存なし) | **0.1746** | 0.0710 |
| MockOrderDep(順序依存あり) | 0.3974 | 0.1713 |

植え込んだ依存性は 2.3 倍の spread として検出された。ただし
**依存性ゼロでも $n=100$ では spread が 0.17 程度出る**。
サンプリング揺らぎだけでこれだけ動くので、実データで順序効果を主張するには
この帰無帯を超える必要がある。**ブートストラップで帰無帯を出す処理は未実装**で、
実データを取る前に追加すべき項目。

## 予測1: 確認

l2r での効果量が AR の再現結果(Qwen3-4B, ブロック反転)とほぼ一致した。

| コーパス | AR (Qwen3) | LLaDA l2r | 差 |
|---|---|---|---|
| Gemini31 | 0.4438 | 0.4584 | +0.015 |
| GPT56 | 0.1640 | 0.1930 | +0.029 |
| GPT54 | 0.3542 | 0.4116 | +0.057 |
| Fable5 | 0.3772 | 0.2928 | −0.084 |
| Opus46 | 0.5692 | 0.7082 | +0.139 |

**5コーパス中4つで差が0.1以内。** 評価器を自己回帰モデルからマスク拡散モデルに
替えても効果量が保存される。枠組みの移植が成立している直接の証拠。

分離は全コーパス・全順序で有意($r$ はすべて正、$p$ はほぼすべて 0.05 未満。
例外は GPT56 の random:2 で $p=0.056$)。

## 予測3: 外れた

「談話構造の慣習が効くなら r2l で分離が弱まる」と予測したが、**5コーパス中4つで
r2l のほうが分離が大きい。** 逆になったのは Opus46 のみ。

また l2r 以外の順序では C も N も水準が一律に上がる(GPT54 で l2r C=0.360/N=0.235
→ r2l C=0.608/N=0.386)。これは順序自体の効果で、因果とは別。

## 順序不変性: 対応つきブートストラップ (B=10000)

同じ200本を全順序で測っているので、順序間の差は**対応つき**で検定する必要がある
(`bootstrap_order_ci.py`)。合成データ由来の「帰無帯0.17」はこの対応を無視して
いたため不適切だった。

| コーパス | spread | 差のある組 | Holm後 |
|---|---|---|---|
| Fable5 | 0.095 | なし | なし |
| Gemini31 | 0.109 | なし | なし |
| GPT56 | 0.161 | なし | なし |
| Opus46 | 0.275 | あり | **あり** |
| GPT54 | 0.324 | あり | **あり** |

Holm 補正後も残る組は2つだけ。

| 組 | 差 | 95%CI | p(Holm) |
|---|---|---|---|
| GPT54: r2l vs random:1 | 0.324 | [0.146, 0.507] | 0.0024 |
| Opus46: l2r vs random:2 | 0.275 | [0.101, 0.449] | 0.0048 |

**差のある組に系統性がない。** さらに GPT54 では **random:1 と random:2 同士が
差を示す**(差 −0.191, $p_{\text{boot}}=0.041$, Holm後 0.175)。つまり観測された
変動は順序の構造ではなく、**引いた置換の個性**による可能性がある。2点では分離
できない。

## 未解決の所見: N のベースラインが浮く

AR では非因果的テキストのブロック反転コストがほぼゼロ(Qwen3/Opus46 で
$-0.0275$)。文が独立なら順序を変えても確率は変わらないはずで、理にかなう。
ところが**マスクモデルでは N が 0.17〜0.24 ある。** スケールの違いでは説明でき
ない(C の比は 2.3 倍だが N は正負が逆)。

分離の一部が内容と無関係な共通オフセットを含んでいる可能性がある。候補は位置の
構造的効果、文脈量の違い、モデル固有の性質。**切り分けには第3の対照群が要る。**

- 無関係な文書から文を寄せ集めた系列(話題の一貫性すら除く)
- 語をシャッフルした系列(統語構造も除く)
- 同一文の繰り返し(トークン列が一致すれば $\sigma$ は厳密に0のはず。
  ただし文頭の空白でトークン化が一致しない可能性があり、その場合に出る値が
  人工物の大きさそのものになる)

## 文シャッフル対照 (2026-11-09): 設計の誤りとして撤回

`shuffle_control.py` は、各因果テキストを**それ自身の文をシャッフルしたもの**と
比較する設計だった。出た数値は劇的に見える。

| コーパス | 群 | 元の中央値 | シャッフル中央値 | 元>シャッフル | $r_{\text{paired}}$ | $p$ |
|---|---|---|---|---|---|---|
| Opus46 | 因果 | 0.41497 | −0.01433 | 96% | 0.9857 | 1.1e-17 |
| Opus46 | 非因果 | 0.17156 | −0.01135 | 88% | 0.8610 | 7.7e-14 |
| GPT54 | 因果 | 0.36008 | −0.02724 | 96% | 0.9873 | 1.0e-17 |
| GPT54 | 非因果 | 0.23541 | −0.01140 | 87% | 0.9057 | 3.7e-15 |

**この対照は何も判定していない。** シャッフル側が 0 になるのは測定結果ではなく
恒等式である。ブロック順 $\pi$ でつないだ系列を $x_\pi$ と書くと、ブロック反転は
ちょうど $x_{\pi\circ\mathrm{rev}}$ なので

$$\sigma(\pi) \;=\; \frac{\log P(x_\pi) - \log P(x_{\pi\circ\mathrm{rev}})}{L} \;=\; -\,\sigma(\pi\circ\mathrm{rev})$$

が恒等的に成り立つ。$\pi \mapsto \pi\circ\mathrm{rev}$ は一様測度を保つ対合だから、
一様に引いた $\pi$ に対する $\sigma$ の分布は**厳密に0対称**で、モデルにも
テキストにも因果にも依存しない。したがって「元>シャッフルが96%」は
$\sigma_{\text{block}}(\text{元}) > 0$ の言い換えにすぎず、既知の事実である。

**機構の傍証**: シャッフル中央値が4つとも**わずかに負**。スクリプトは恒等置換を
除外しているがその反転は除外していないので、対 $\{\mathrm{id}, \mathrm{rev}\}$ から
$+\sigma(\mathrm{id})$ 側だけが抜ける。$n=4$ なら偏りは
$\sigma(\mathrm{id})/(n!-1) \approx 0.415/23 \approx 0.018$ 負方向で、観測値と
オーダーが一致する。

このスクリプトは記録として残すが、**結論に使ってはならない**。

## 次の実験(本命): 方向中立な評価器

**これが論文の中心測定になる。** 沙川の $\sigma$ は AR モデルで測られるが、AR モデルは
**片方向にしか訓練されていない**。だから $\sigma > 0$ の原因を

- (i) テキストが因果の矢を持つ
- (ii) **評価器が片方向にしか訓練されていない**

に分離することが AR モデル単体では**原理的に不可能**である。マスク(双方向)
モデルに置き換えると (ii) が構成的に消える。$p_\theta(x_k \mid x_{-k})$ は両側文脈を
見るので、$x$ でも $\tilde x$ でも各予測が使える情報は**同じ文脈トークンの多重集合**で
あり、配置だけが違う。分解がどちらの向きも特権化しない。

| 結果 | 読み |
|---|---|
| $\sigma_{\text{masked}} \approx 0$ | $\sigma$ は AR 分解の性質であってテキストの性質ではない |
| $\sigma_{\text{masked}} > 0$ だが $r \approx 0$ | 文法・語順は測るが因果は測らない |
| $\sigma_{\text{masked}} > 0$、$r$ も同程度 | 非対称性はテキストにある(ただし熱力学的読みは別問題) |

### 規模の交絡と、その潰し方

再現解析では **GPT-2 (117M) がブロック水準で5コーパス中3つで分離できず、
Qwen3-4B-Base は5/5**。BERT-base は 110M なので、$\sigma_{\text{BERT}} \approx 0$ が
出ても「双方向だから」か「小さいから」か分離できない。これは査読で必ず突かれる。
対照を2段構えにする。

1. **規模一致対**: `bert-base-uncased` (110M, masked) ↔ `gpt2` (117M, causal)。
   同世代・ほぼ同サイズ・比較可能な訓練コーパス。**ここでの差は規模ではなく
   方向性**。同一パイプラインで両方計算するので、トークン化・ブロック分割・
   統計がすべて揃う。
2. **大規模双方向**: `GSAI-ML/LLaDA-8B-Base` を PLL で読み、`Qwen3-4B-Base` の
   AR と比べる。規模への疑いが残らない。

`bert-large-uncased` (340M) も入れて、マスク側の結果が最小モデルの人工物で
ないことを示す。

### 測る量についての明示

ここで使うマスクモデルのスコアは**擬似対数尤度**
$\mathrm{PLL}(x) = \sum_k \log p_\theta(x_k \mid x_{-k})$ であって、**どの同時分布の
対数確率でもない**(長方形テスト、arXiv:2605.16378)。したがって
$\mathrm{PLL}(x) - \mathrm{PLL}(\tilde x)$ は well-defined なスコア差だが
**KL ダイバージェンスではなく**、$\sigma = D_{\mathrm{KL}}(P_\to \| P_\leftarrow)$ という
同定は成立しない。

**これは欠陥ではなく、この実験の設計そのものである。** 検定対象は
「評価器の方向バイアス」であり、それには方向中立なスコアラーが正しい道具である。
真の対数確率が要る場合は任意順連鎖律(`aoar_core.py`)が別ルートとしてあり、
その代償が自由パラメータ $\pi$ である。

### 2種類の反転を分けて測る

- **トークン反転**は文法を壊すので、どのモデルでも $\sigma$ が大きく出る。
  これは統語の話で因果についてほとんど何も言わない。
- **ブロック反転**は各文を保ったまま文順だけ入れ替えるので、残るのは談話順序。
  沙川の主要結果もブロック水準なので、**比較はブロックで行う**。

## 決定実験: 書かれたブロック順の位置(GPU 不要)

`block_order_pll.py` + `icr_job_blkord.sh` + `merge_blkord.py`。

**ここまでの測定はすべて因果テキスト集合と非因果テキスト集合の比較**であり、両集合は
因果順序以外でも違う(トークン数が5コーパス中4つで有意差、生成プロンプトが別、
非因果テキストも談話としては一貫している)。したがって $r > 0$ は
「σ が**書かれた順であること**に反応している」でも等しく説明がつく。
**集合間比較では原理的に分離できない。**

この検定は**テキスト内**で行う。同じ文を $4! = 24$ 通りすべての順で連結し、

$$\sigma(\pi) = \frac{S(x_\pi) - S(x_{\pi\circ\mathrm{rev}})}{L}$$

を全列挙して、書かれた順 $\sigma(\mathrm{id})$ がその中で何位かを見る。長さ・語彙・
文体・話題は構成上すべて同一なので、交絡が残らない。

| 結果 | 読み |
|---|---|
| 因果が上位・非因果が中位 | σ は因果順序を特異的に測っている |
| **両群とも同じ位置** | **σ が測っているのは「書かれた順であること」。因果ではない** |

### 任意順連鎖律は要らない

統計量が**同一トークン多重集合の並べ替え同士の順位**なので、比較可能なスコアであれば
何でもよい。反対称性 $\sigma(\pi) = -\sigma(\pi\circ\mathrm{rev})$ はスコア関数の形に
よらず純粋に形式的に成り立つ。したがって PLL で足り、**CPU で走り、しかも規模一致対の
両方**(bert-base 110M 双方向 / gpt2 117M 片方向)で実行できる。同じ統計量が
方向性の問いと因果の問いに同時に答えるので、LLaDA 単独より論文として強い。

### 中間順位を使う理由(重要)

順位を `<=` で数えてはならない。ブロック順を**まったく区別しないスコア**では σ が
全置換で厳密に 0 になり、`<=` count は $k/k = 1.00$ を返す。「書かれた順が最も
コストの高い配置」と読めてしまうが、実際はモデルが配置を識別できていないだけ。
同値を割る中間順位 $(\#\{<\} + \tfrac12 \#\{=\})/k$ なら、その場合ちょうど **0.50** に
落ちる。これが本検定の帰無水準である。self-test で両方を明示的に確認している。

### 検証済み

`block_order_selftest.py`(重み不要、**実行済み・全通過**):

- 置換集合が**反転について閉じている**こと、恒等置換を含むこと($n=3,4,6$)
- $n=4$ で 24 通り全列挙になること
- σ の 24 値が $\pm$ 対をなし総和がゼロになること(`shuffle_control.py` を無効化した
  反対称性そのもの。ここでは設計上の性質で、**成り立たなければ簿記が誤り**)
- **順位が反対称性に固定されていない**こと。ランダムスコア400試行で percentile が
  0.0208–0.9792 の 24 値すべてを取り、平均が 0.4866(理論値 0.5)
- 順序を無視するスコアで percentile がちょうど 0.50、かつ `<=` count なら 1.00 に
  なること(中間順位を使う理由の明示)
- 書かれた順を報いるスコアで percentile が 0.9792 になること

`merge_blkord.py` も合成データで検証済み(`merge_blkord_mocktest.log`)。
